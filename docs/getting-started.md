## Requirements

| Item | Minimum |
|---|---|
| **OS** | Ubuntu 22.04+, Debian 12+, or Raspberry Pi OS Bookworm/Bullseye (headless) |
| **Architecture** | x86_64, aarch64, armv7l (32-bit Pi 3) |
| **RAM** | 512 MB (1 GB recommended; the frontend build needs ~800 MB — the installer adds swap automatically on low-RAM systems) |
| **Storage** | 500 MB free (Pi users: use a high-endurance SD card or move the database to USB) |
| **Network** | Static IP or DHCP reservation recommended for your server |

> **Raspberry Pi recommendation:** A **Raspberry Pi 4 (1 GB or more)** is the recommended minimum for a smooth experience. The Pi 4's Cortex-A72 cores are roughly 3–4× faster than the Pi 3B+'s Cortex-A53 for the single-threaded Python/SQLite workload that MyNet uses. A Pi 3B+ will run MyNet but may feel sluggish, particularly on the Monitoring and Switches pages. A Pi 4 or better eliminates this.

> **Note:** The setup script installs all software dependencies (Python 3.10+, Node.js 20, nginx) automatically. You do not need to pre-install them.

## Installation

**1. Clone the repository**

```bash
git clone https://github.com/StableFlux/MyNet.git
cd MyNet
```

**2. Run the setup script as root**

```bash
sudo bash setup.sh
```

The script will:

1. Detect your OS, architecture, and available RAM
2. Add swap space if needed (for low-RAM systems like Pi 3B+)
3. Install system packages: Python 3.10+, Node.js 20, nginx, fonts-dejavu-core
4. Build the React frontend with Vite
5. Create a Python virtual environment and install backend dependencies
6. Generate a secure `JWT_SECRET_KEY` and write `/opt/mynet/.env`
7. Configure nginx as a reverse proxy on port 80
8. Create and enable a `mynet` systemd service
9. Configure UFW to allow port 80 (if UFW is installed)
10. Run a health check and print the URL

When it finishes you will see:

```
════════════════════════════════════════
  MyNet is installed and running!
════════════════════════════════════════

  App:      http://192.168.1.100

  Open http://192.168.1.100 in your browser to complete setup.
```

## First Run — Setup Wizard

Open the URL shown after installation. If no users exist yet, MyNet shows a **first-run setup screen**.

**Create your admin account:**

| Field | Notes |
|---|---|
| Username | Lowercase letters, numbers, and underscores. Cannot be changed later. |
| Display Name | Shown in the UI and event log. |
| Password | Minimum 8 characters. |
| Email | Optional. |

Click **Create Account** — you will be logged in immediately as an admin.

> **Tip:** If you have a backup from a previous installation, you can restore it directly from the first-run screen instead of creating a new account. See [Backup & Restore](features/backup-restore.md).

## Environment Configuration

The environment file lives at `/opt/mynet/.env`. It is generated by the setup script and is never committed to version control.

```bash
sudo nano /opt/mynet/.env
```

After editing, restart the service:

```bash
sudo systemctl restart mynet
```

### Available Variables

| Variable | Default | Description |
|---|---|---|
| `JWT_SECRET_KEY` | Auto-generated | Secret used to sign JWT tokens. Auto-generated on first run if blank. **Keep this secret.** |
| `JWT_EXPIRE_MINUTES` | `480` | Session length in minutes (default 8 hours). |
| `DB_PATH` | `/opt/mynet/data/mynet.db` | Path to the SQLite database. Move to a USB drive on Pi to reduce SD card wear. |
| `CORS_ORIGINS` | *(LAN auto)* | Comma-separated list of allowed browser origins. Leave blank for automatic LAN detection. Set explicitly for internet-facing deployments (e.g. `https://mynet.example.com`). |
| `PIHOLE1_URL` | *(blank)* | URL of your first Pi-hole (e.g. `http://192.168.1.2`). See [Pi-hole Integration](features/pihole.md). |
| `PIHOLE2_URL` | *(blank)* | Optional second Pi-hole URL. |
| `PIHOLE_POLL_INTERVAL_SECS` | `300` | How often to poll Pi-hole stats (seconds). |
| `MONITORING_MAX_CONCURRENT_PINGS` | `20` | Maximum simultaneous ICMP pings. Raise to 50+ on capable hardware. |
| `MONITORING_DEFAULT_INTERVAL_SECS` | `60` | Default ping interval for new monitored devices. |
| `MONITORING_FAILURE_THRESHOLD` | `3` | Consecutive failures before a device is marked offline. |
| `QR_LABEL_WIDTH_PX` | `696` | Label width in pixels (Brother P950NW 24mm tape @ 300 dpi). |
| `QR_LABEL_HEIGHT_PX` | `272` | Label height in pixels. |

## Updating

```bash
cd mynet
git pull
sudo bash update.sh
```

The update script rebuilds the frontend, reinstalls Python dependencies, and restarts the service. Your database and `.env` file are never touched.

## Service Management

MyNet runs as a systemd service named `mynet`.

```bash
# Status
sudo systemctl status mynet

# Restart
sudo systemctl restart mynet

# Stop
sudo systemctl stop mynet

# Start
sudo systemctl start mynet

# View live logs
sudo journalctl -u mynet -f

# View last 100 log lines
sudo journalctl -u mynet -n 100
```

**nginx** serves the frontend and proxies API requests:

```bash
# Reload nginx config
sudo systemctl reload nginx

# Test nginx config
sudo nginx -t
```

## HTTPS Setup

MyNet ships with an HTTPS-ready nginx template. To enable it:

**1. Obtain a certificate** (e.g. using Let's Encrypt):

```bash
sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d mynet.example.com
```

Or generate a self-signed certificate for LAN use:

```bash
sudo openssl req -x509 -nodes -days 3650 -newkey rsa:4096 \
  -keyout /etc/ssl/private/mynet.key \
  -out /etc/ssl/certs/mynet.crt \
  -subj "/CN=mynet.local"
```

**2. Edit the nginx config** at `site/deployment/nginx.conf`:

- Uncomment the HTTPS server block and HTTP redirect block
- Comment out or remove the plain HTTP server block
- Set `ssl_certificate` and `ssl_certificate_key` to your certificate paths
- Replace `mynet.example.com` with your domain or IP

**3. Apply the config:**

```bash
sudo cp site/deployment/nginx.conf /etc/nginx/sites-available/mynet
sudo nginx -t && sudo systemctl reload nginx
```

**4. Set CORS_ORIGINS** in `.env`:

```
CORS_ORIGINS=https://mynet.example.com
```

> **Security note:** For internet-facing deployments, also enable [credential encryption](features/settings.md#encryption) in Settings.

## Uninstalling

```bash
# Stop and disable the service
sudo systemctl stop mynet
sudo systemctl disable mynet
sudo rm /etc/systemd/system/mynet.service
sudo systemctl daemon-reload

# Remove nginx config
sudo rm /etc/nginx/sites-enabled/mynet
sudo rm /etc/nginx/sites-available/mynet
sudo systemctl reload nginx

# Remove installed files (preserves the git repo)
sudo rm -rf /opt/mynet
```
